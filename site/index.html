Sentinel by IklwaLabs v0.1.0

Local-first network visibility and threat detection.

Sentinel watches the traffic on your machine, reconstructs the connections that carry it, stores what it finds in a local database, and tells you what is happening. No account, no cloud service, nothing leaves the machine.

What it does

  • Enumerates real capture interfaces

    Through Npcap on Windows, libpcap on Linux and macOS. Wired, wireless, loopback, tunnel and virtual adapters are classified, and an adapter that cannot be captured says why instead of being offered.

  • Captures live traffic

    From a selected adapter, on a dedicated thread, with backpressure that is counted rather than hidden. An ingress queue that overflows is visible in the interface.

  • Decodes L2 to L4 itself

    Ethernet, VLAN, IPv4, IPv6, ARP, TCP, UDP and ICMP through an own bounds-checked decoder, so truncation and IP fragmentation are handled explicitly rather than guessed at.

  • Reconstructs bidirectional flows

    Keyed on a canonically ordered endpoint pair with initiator detection from port roles, so a connection appears once with both directions attributed correctly.

  • Analyses PCAP files through the same pipeline

    Offline results match live capture exactly, because there is one decoder and one flow engine behind both.

  • Reports incomplete data as incomplete

    Packet loss is tracked separately for the driver, the ingress queue and the decoder, and every surface says which of the three lost frames.

  • Stores everything in SQLite, locally

    One batched writer thread, append-only migrations, configurable retention. There is no code path that opens an outbound connection.

    • Not in this release

    These are absent from the interface rather than faked. A threat rule that cannot fire, or a device list inferred from nothing, would be worse than an honest gap.

    • Threat rules. No detection engine ships in this release. The rule model and its evaluation contract are designed in docs/DETECTION_ENGINE.md, but presenting a rule that cannot fire would be worse than showing nothing.
    • Process attribution. Sentinel reports which process owns a connection only where the platform exposes it without a kernel driver. Nothing is guessed from port numbers.
    • Device inventory. There is no list of devices on the network. Sentinel observes this machine's traffic, not the topology around it.
    • DNS correlation. DNS queries are decoded and shown as flows. They are not resolved into hostnames or joined against other traffic yet.

    Command line

    The CLI is a thin client over the same engine as the desktop application, so the two cannot disagree about what your network is doing.

    CommandPurpose
    sentinel interfacesList capture interfaces and whether each one is ready.
    sentinel doctorReport whether capture is possible in this process, and what to do when it is not.
    sentinel capture --duration 30Capture live traffic for a fixed window.
    sentinel statusWhat the current session is doing.
    sentinel analyze capture.pcapAnalyse a PCAP file offline, no privileges needed.
    sentinel export flows.csvExport stored flows as CSV or JSON.
    sentinel pruneApply retention now, with --dry-run to see what would go.
    sentinel versionVersion, schema and platform.

    Add --json for machine-readable output, -v for more detail, -q for less.

    Build from source

    Rust 1.95 or newer, Node.js 20 or newer, and a capture driver: Npcap with its SDK on Windows, libpcap-dev on Linux, nothing on macOS.

    1. git clone https://github.com/IklwaLabs/assegai-sentinel.git
    2. cd assegai-sentinel
    3. cargo build --release
    4. cargo test
    5. cargo build --release -p sentinel-desktop --features custom-protocol
    6. cd apps/desktop/frontend && npm install && npm run build
    • The custom-protocol feature is not optional. Without it the desktop binary looks for the Vite dev server instead of the assets embedded in the executable, and opens a black window.
    • The repository is private. You need an invitation from IklwaLabs to clone it.
    • docs/Sentinel-Reference.pdf is the whole product in one document: architecture, how to run it, how to control it, troubleshooting.

    Verify a download

    Every platform's artifact set includes a SHA256SUMS.txt. Compare it before running anything:

    sha256sum -c SHA256SUMS.txt
    • Artifacts are served over TLS from the GitHub release, so the checksum is a check against tampering in transit, not against a compromised account.
    • macOS artifacts are unsigned. That is why the checksum matters more there than elsewhere.

    Questions

    Does anything leave my machine?

    No. There is no code path in Sentinel that opens an outbound connection. The database is a local SQLite file, and the interface is local. SECURITY.md documents this and the reasoning behind it.

    Why does capture fail on Windows until I run as Administrator?

    Reading frames needs an elevated token. Sentinel reports 'notElevated' through 'sentinel doctor' before you start a session, rather than failing later with a driver error code.

    Why is the macOS build unsigned?

    Notarisation needs an Apple developer account. Until there is one, right-click the app and choose Open, or clear the quarantine attribute. The SHA256SUMS.txt file lets you verify the download first.

    Can the Android build capture live traffic?

    No. It needs a userspace TCP/IP stack over an app-owned VPN slot, which is not implemented. The APK analyses PCAP files and lists interfaces, and reports live capture as unavailable rather than pretending.

    Where is my data stored?

    In a SQLite database under your platform's application-data directory, named by sentinel-platform so each platform uses its own conventions. 'sentinel version' reports the schema version.

    Does it detect threats?

    Not in this release. The product is named for it and the roadmap commits to it, but v0.1.0 ships the capture-to-storage pipeline and none of the rules. docs/DETECTION_ENGINE.md explains the design.
